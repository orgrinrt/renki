# the-posix-reader

How a tool that cannot link Rust reads the same manifests, its layers and its
predicates, and how another repository takes only that reader.

## How it is made

Three ways it could be made:

1. By hand, in POSIX `sh` and `awk`, held to one suite both readers run.
2. Generated from the Rust: from the schema, the order, the merge rule. No
   generator exists for any of it, and the logic to generate is a TOML reader,
   a merge and a predicate evaluator, not a table of constants. A generator is
   a compiler from Rust to `awk`, bigger than what it would generate.
3. nutshell's TOML module lowered to `sh`. It is bash today and calls `taplo`
   or `yq`; renki would then depend on nutshell and on a binary a POSIX host
   may not have, and whether `nut-lower` can lower it is not established.

Decision: 1. What op made the floor, "at least conformance and parity tests",
is what holds the two together, and it holds a hand-written reader exactly as
well as a generated one. A generator stays a later thing only if the suite
shows drift it cannot catch; nothing here forecloses it. 3 is out because a
POSIX reader that needs a bash program and a TOML binary is not a POSIX
reader. So the question `toml_backend_order_taplo_ahead_of_mikefarah_yq_which_reads_i`
does not bear on renki.

## What it reads

The POSIX reader does not claim all of TOML. It reads a stated subset and
refuses, with the file and the line, anything outside it, so it never reads a
manifest wrongly: it reads it or says it cannot.

- In: comments; `[table]` and `[dotted.table]` headers; `[[array.of.tables]]`;
  `key = value` with bare and dotted keys; basic strings with the escapes
  `\"`, `\\`, `\n`, `\t`; literal strings; integers; booleans; one-line arrays
  of those scalars.
- Out, refused by name: multi-line strings, inline tables, arrays over several
  lines, quoted keys, floats, dates, `\u` escapes.
- The layers, `meta.overlays.include` with the same glob rule, the order, the
  merge rule and the predicates are read in full: the subset limits the
  syntax of one file, never the behaviour across files.

## What it answers

The common answer of both readers is a dump: the merged view, one line per
leaf, `<dotted path> = <value>`, an array of tables indexed as `name[0]`, the
value in one canonical TOML form, the lines sorted bytewise. `get <key>` is
the dump's line for a key. The Rust reader gains the same dump, so both are
compared on the same bytes.

## The suite

One directory of fixtures, each a set of manifest files with its layers and
an expected dump, or an expected refusal. A fixture outside the subset carries
the Rust dump and the POSIX refusal. One test in renki runs every fixture
through both readers and compares each with what the fixture expects: the
conformance is each reader against the fixture, the parity is that both meet
the same file. A behaviour is added to both readers or to neither, since the
fixture that pins it fails for the reader that lacks it.

## Where it sits

Everything the POSIX reader needs is under one top-level directory of renki,
`posix/`, and it reads nothing outside it. A consumer adds renki as a
submodule at a pinned revision with a sparse checkout of `posix/`, and sources
the reader from there. The same revision is what its Rust side pins, which is
"the same renki as in the rust one". The suite's fixtures sit under
`posix/conformance/`, so a consumer that wants to run them against its copy
has them in the same sparse path.

`sh` here means the POSIX shell and `awk` the POSIX awk: no `local`, no arrays
in the shell, no `gawk` extensions. A shell predicate runs through `sh -c`
the same as the Rust reader runs it.

## The subset, again, after reading git-shook's reader

git-shook's awk reader at 24ceb79 (`git-shook:144-242`) reads `run = [...]`
arrays that span lines, and the shook manifests written for it use them. A
subset that refuses them would refuse the first manifests the POSIX reader is
for. So arrays of scalars over several lines are in, and only arrays nested in
arrays stay out. A trailing comment after a value, which git-shook refuses
(`:242`), is in: the Rust reader takes it and a refusal there would be the two
disagreeing on a file both can read.
