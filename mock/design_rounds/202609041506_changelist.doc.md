# doc changelist

The launcher's design document gains the third thing the launcher answers
without the engine, which is the tool's own. It descends from the workspace
design `.shared/designs/renki-configuration.md`, whose section "What every
launcher answers itself" names the two the crate owns, and from the topic file
`202609041506_topic.a-tools-own-launcher-commands.md`, which says why the
second consumer of that design needs one the crate cannot own.

## What lands

- `mock/crates/renki/DESIGN.md.tmpl`: a section "A tool's own commands",
  between the configuration and the retried install. `Tool::commands` is a
  table of `Command`, each a name, a sentence and a function; the launcher
  tries it where it tries `config`, before a root is required; the function
  gets an `Invocation` carrying the tool, the cwd, the root where one was
  found, the resolved settings and the arguments after the name, and answers
  the way a hook does. The resolved row goes public for it, unchanged in
  shape. A command is not a hook, and the descriptor check refuses an empty
  name, a name the crate's own queries take first, and two commands of one
  name.
- `README.md` at the repo root, which is hand-written rather than rendered:
  one paragraph under "What the launcher answers on its own".

## Claims the source changelist will carry

`Command` and `Invocation` on `tool.rs` with `commands` on `Tool` and in
`CONVENTIONS`; the three refusals in `Tool::defect`, const; the resolved row
public with accessors; the dispatch in `lib.rs` between the `config` query and
the root requirement; and the tests for each, the refusals as const
assertions and the dispatch as a run against a tool with a command and no
root. Each is a `CHANGE` block there with its own verification.
