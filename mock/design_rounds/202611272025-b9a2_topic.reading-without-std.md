# reading-without-std

Where the reading of a manifest lives, reopened: the first decision of
`where-the-manifest-reading-lives` put it in a `std` crate, and the lints this
repository runs bind every crate but the launcher to `no_std`, no alloc and
the stack's types. Reading a file does not need `std`, and a TOML parser of
the stack's own could replace the two TOML crates renki carries, if it is
shown to read the newest TOML exactly.

## The intent

- The reading of a manifest passes `no-std`, `no-alloc` and the `no-bare-*`
  lints as they stand: no exemption, no allow-marker, no ratchet.
- File i/o without `std`, by a vehicle stated per platform renki supports.
- What no alloc means for a manifest of unknown size, said.
- The stack's own TOML parser in place of `toml` and `toml_edit`, a crate of
  its own in the repository that holds the stack's TOML work, generic, naming
  none of its users, held to the newest TOML specification by the official
  toml-test suite, valid and invalid cases both, with the number in the round.
- renki depends on that one crate and not on the rest of that repository; the
  crate is published before renki's next release candidate.
- Everything else of this round stands: the layers, the order, `meta`, the
  predicates, the merge and the POSIX reader.

## The two feasibility questions

Answered by two committed sketches before any design here.

1. `202611272130_no-std-file-reading-on-unix`: WORKS. A `#![no_std]`,
   no-alloc crate reads a whole file into a caller's buffer, lists a
   directory, reads a variable and runs `sh -c` in a directory with its exit,
   through the C library alone (the `libc` crate, default features off). It
   runs on x86_64 linux and builds with core only for linux gnu and musl,
   macOS on both architectures, freebsd, netbsd, openbsd and illumos, which
   are the platforms `renki-dirs` names. Only where errno lives differs per
   C library. A file's size is known from `fstat` before a byte is read, so a
   buffer too small is refused with the size it needs.
2. `202611272150_a-no-std-toml-parser-against-toml-test`: WORKS. A
   `#![no_std]` TOML reader with no alloc and no unstable feature, building on
   stable, passes every case the official suite carries:

   | spec  | valid     | invalid   |
   | ----- | --------- | --------- |
   | 1.0.0 | 208 / 208 | 501 / 501 |
   | 1.1.0 | 218 / 218 | 494 / 494 |

   from `toml-test-data` 2.14.1, compared through `toml-test` 2.1.0's own
   value equality. Two deliberate breaks turned 16 invalid and 6 valid cases
   red per version, so the harness sees what it claims to. The reader hands
   what it reads to a visitor, keeps its duplicate-definition index in a slice
   of nodes the caller gives (28 bytes a node, at most one per two bytes of
   text, 0.333 per byte the most the suite needed), and leaves strings as
   spans of the text, decoded on demand.

## Where the reading lives

1. In `renki-config`. It would stop being the contracts, and every call into
   the C library is `unsafe` code in a crate that reads nothing.
2. In `renki-manifest`, now `no_std`. Its own thing is reading a manifest off
   the disk; the contracts stay as they are.
3. A third crate for the C calls alone, under `renki-manifest`. A crate for
   one thing nothing else needs yet; a second user is when it is split out.

Decision: 2. `renki-manifest` stays, `#![no_std]`, no alloc, and passes the
lints as they stand. Its i/o is a `Host` trait with one implementation per
target family, over the C library through `libc`; a target with no
implementation does not build. The `unsafe` is in that one module.

## Memory

A manifest's size is not known until it is found. The caller gives the room,
`Room`, which holds the text of every layer read, back to back, and the
parser's index. A file that does not fit is refused with the size it needs, so
a caller with a fixed room learns how big to make it, and one with an
allocator gives one that size and reads again. Nothing is read twice in one
read: the size of each file is known before its bytes are.

## The parser

A crate of its own, `tomlfuse-parse`, in the tomlfuse repository beside
`tomlfuse-core`: `#![no_std]`, no alloc, stable, generic. It reads one
document from the caller's text, hands every table header, key and value to a
visitor, and refuses with the byte offset anything the spec refuses. The
sketch is its first draft. It is held to toml-test there, valid and invalid,
for every spec version the data carries.

renki depends on `tomlfuse-parse` alone. Since a git dependency keeps a crate
from publishing, `tomlfuse-parse` is published first, and renki's next
release candidate takes it from the registry.

The TOML store, `Toml`, is renki-config's `Store` over `tomlfuse-parse`, in
`renki-manifest`: it answers keys and shapes from the visitor's spans and
writes a key by editing the text at its span, so comments survive. `toml` and
`toml_edit` leave renki: every TOML file the launcher reads, its two
configuration files, a tool's descriptor, a crate's `Cargo.toml` and the
registry's rows, goes through the one parser.

## Merging without a tree

The merged view is not built: it is the stack of layers, answered key by key
by `renki-config`'s `stacked`. `Manifest::read::<T>` deserialises through
`serde` with its default features off, from a deserializer over the stack, so
a tool's type borrows its strings from the room. A type that wants owned
values owns them by its own allocator, never by the reader's. The dump walks
the leaves in byte order of their dotted path with the room's index, and
writes into a `core::fmt::Write` sink.

## What stays

The layers, their order, `meta`, includes to a fixed point, the predicates,
the merge rule and the POSIX reader, as `layers-meta-and-predicates` and
`the-posix-reader` decided. The one call stands, with the room as its one
more argument: `renki_manifest::read::<T>(path, &mut room)`.

## Against the store contract

The first source stopped on six points where the design above cannot be
built as written; `mock/research/202611272355_the-no-std-reading-against-the-store-contract.md`
records each with its line and its failure. Decided, all six as proposed
there:

- The parser's index is the document. `tomlfuse-parse` keeps every node it
  read, each with its key's span and its value's span, and offers a read view
  over the filled slice: a lookup by dotted path, a node's children, the
  elements of an array of tables. The store keeps nothing of its own.
  `Store::parse` takes the caller's index along with the text, and the room
  gives it; `nodes_for` still bounds it.
- A decoded string lives in the room. The room holds a decode shelf as long
  as its text, since a decoded TOML string is never longer than its source:
  each escape decodes to at most its own length and a line-ending backslash
  removes bytes. A test runs every escape TOML 1.1.0 has and holds the claim.
- `Literal::List` carries the store's own handle for the list, and
  `Store::items` walks the handle, so an array of tables is a list like any
  other with no list text of its own.
- `renki-config` comes off bare types in this round: its contract takes the
  stack's string and number types, and every `lint:allow` marker in it goes.
  `renki-manifest` depends on the same crates and passes the lints outright.
  The bare-type lints do not judge the signature of a method in an impl of a
  trait another crate defines, since the trait's owner is where that
  signature is chosen; that is the lints' own change, made where they live.
- The room borrows its memory. `Room<'r>` is three slices the caller hands
  in, the text, the decode shelf and the nodes; `Rooms<TEXT, NODES>` owns
  them in fixed arrays for a caller with no allocator. A caller with an
  allocator gives slices of the size `BadRead::Room` names and reads again,
  and in renki that retry is written once, in the launcher crate.
- Spawning a process is the feature `processes`, off by default. It carries
  the `shell` predicate and the untracked-layer check alike. Without it a
  `shell` predicate is refused by name and the untracked check is not run,
  and the dump says it was not. `renki`, the launcher, turns it on.

And three smaller points: the room holds a path shelf, where the base path and
each joined include path are written with their terminating NUL, and a
`BadRead` names a file by its place there; the store reads TOML 1.1.0; and the
writer's fixtures record what the design calls for. Four of them differ from
what `toml_edit` wrote, each a named fixture: a key inside an inline table is
edited in its braces, not added again as a second table; a key beside a
multi-line string is the real key, not a line inside the string; a key holding
a multi-line string has its whole value replaced; and a key under a `[[name]]`
header is edited in that element. The change of behaviour is in the
changelog.

## The lints, the foreign trait and the lend

Three points the section above left to others came back decided, and they
change its fourth bullet.

- Which crates the bare-type lints read. Among: the lints apply only where arvo
  is a dependency, so `renki-manifest` finishes now on `core`'s types;
  `renki-config` and `renki-manifest` publish under new names once the stack's
  string and number crates are on the registry; or the reading is held until
  then. Decided: the lints read only the crates that take arvo. That is the
  lints' own change, made where they live. `renki-manifest` takes notko and no
  arvo, speaks `&str`, `usize` and the C library's integers, and does not wait
  on the stack's string and number crates. `renki-config` takes no arvo
  either; its port off bare types waits on those crates as its design says,
  and is not this round's.
- An impl of a trait another crate owns. Among: the lints skip such an impl's
  signature; they do not, and the bare types that signature fixes sit behind
  a trait or newtype of the implementer's own; they do not, and each site
  carries an allow-marker. Decided: no skip, the trait is wrapped. No marker
  and no exemption. The skip named in the section above is withdrawn. The TOML
  store implements no `tomlfuse_parse::Visitor` at all: it reads through the
  parser's document view with the visitor `()`.
- Memory as a contract. Every shelf a read takes, the parser's index and the
  room's four, is lent through `notko::lend::Lend`, generic over the lender,
  and a shelf that falls short is refused with the `notko::lend::Exhausted` it
  gave. `tomlfuse-parse` takes its index so and refuses with
  `ErrorKind::Exhausted`, whose `wanted` is one more than it held, the least a
  read stopped partway is known to want. `Store::parse` takes its index so,
  and `BadRead::Room` carries the shelf and its `Exhausted`. dollop, the
  allocation contracts, is on no registry and in no manifest, so nothing takes
  it; where it lands it is one more lender.

## What the store spells, and the lints by replacement

The source stopped again where the TOML store is written, on two points
recorded in `mock/research/202611281110_what-the-store-spells-has-no-shelf.md`,
and the lints' scope as they landed changed the host. Decided:

- What the store hands out that is no text of the document as written, a
  string with its escapes decoded and a key spelled whole with its tables,
  is written into a second shelf the store is given with the index. Among: a
  second lend to `Store::parse`; a key as the store's handle, walked by
  segment, beside a shelf for strings; a store cell carrying bytes beside its
  node. Decided: the second lend, with one shape rule: both shelves reach
  `Store::parse` through one contract of `renki-config`'s, `Shelves`, whose
  implementation hands out both, never as two loose parameters, so a managed
  allocator can implement it later and nothing outside it names how memory is
  lent. The store knows the whole need once it has read the text, so a short
  shelf is refused with the whole need, by `ShortShelf` naming the shelf by a
  two-variant `StoreShelf`. The room's decode shelf becomes this spelling
  shelf, sized by that answer and not by the text.
- The bare-type lints, as they landed, each read a crate that takes the
  crate of its replacement: arvo's for numbers and strings, notko's for
  `Result` and `Option`. `renki-manifest` takes notko and not arvo, so its
  numbers and strings stay `core`'s and every fallible or optional answer it
  gives, the host's included, is notko's `Outcome` or `Maybe`.
- A store's keys and a list's items were walked through `core::iter::Iterator`,
  whose `next` answers in `Option`, a signature `renki-manifest` cannot wrap
  from its side. They are walked through `Walk`, a trait of `renki-config`'s
  answering `Maybe`, which every store implements and the contracts loop over.
- Still open: the deserializer `read::<T>` goes through, whose `serde` traits
  answer in `Result` and `Option` by their own signatures. Among: the
  deserializer in a crate of its own that takes no notko; a read trait of
  `renki-config`'s that a tool's type implements in place of `serde`; holding
  `read::<T>` until the lints' owner rules on another crate's trait. Not
  settled by this reopening; `read::<T>` and the deserializer wait on it.
- The writer: `Store::set` took the text and nothing else, and setting a key
  at its value's span needs the text read, which needs memory the contract
  did not give it. Decided, as the shelves above decide memory: `Store::set`
  takes the document the store parsed, whose text it writes from, so writing
  asks for no memory beyond what the parse was given through `Shelves`.
