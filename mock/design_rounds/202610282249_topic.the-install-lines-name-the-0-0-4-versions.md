# the-install-lines-name-the-0-0-4-versions

The release round for `0.0.4` of `renki`, and `0.0.2` of `renki-dirs` and
`renki-config`. Op's words, 28 October 21:04, quoted whole: "You may do the
patch bump on renki and release on crates io". The intent in them is a patch
release of `renki`, prepared in the repository; the publish itself is not part
of this round, and nothing here runs one.

The two smaller crates move with it because the previous round renamed six of
their public types, `Kind`, `Source` and `Sealed` in `renki-dirs` and `Source`,
`Resolved` and `Sealed` in `renki-config`, which breaks every consumer of the
`0.0.1` names. They are still `0.0.x`, where a patch bump is the one that
carries a break, so each goes to `0.0.2` and the requirement `renki` names for
each follows. The other changes since `0.0.3` are in `renki` alone: one
engine build per key under a target directory of that key's own, a collector
that leaves a build in progress, and the `--engine` scratch build running in the
repository's root.

Each crate's readme carries an install line naming the version the manifest
ships, pinned by the readme truth test in every crate, so a bump of the three
manifests is a bump of the three install lines with it. The two smaller crates'
readmes are doc templates to the gate, which is why a round opens for what is
otherwise a version number. The rendered `docs/STRUCTURE.md` follows them when
the documents regenerate.

Nothing else in the prose changes. The root readme's line moves with the
manifest outside the gate, the changelog is a root file the gate does not read
and gains the block for this release, and `Cargo.lock` is regenerated by cargo.
