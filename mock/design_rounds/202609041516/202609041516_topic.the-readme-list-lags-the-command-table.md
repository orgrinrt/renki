# the-readme-list-lags-the-command-table

A fix round, standing alone the way a defect found and fixed does. The round
`202609041506` closed with `Tool::commands` on the descriptor and a paragraph
about it in the root readme, and the push gate went red on the readme truth
test: the readme names `Tool::commands`, and the test's list of things this
crate has does not carry it.

That list is the point of the test. Every row in it is referenced in a way the
compiler checks, so a rename that leaves the readme behind fails the build of
the test rather than shipping a readme that names a type nobody has. A new
name the readme uses has to go on the list with a reference beside it, and the
count the test asserts moves with it. The round that added the name did not
do that, because the test lives under `tests/` and the source changelist's
verifications were all `cargo test -p renki` over the lib, which does not run
the integration tests. The push gate does, which is why it was caught there.

So the row, the reference and the count. Nothing else changes, and the
templates do not change at all, since the readme paragraph the list now
admits was written in the round before this one.
