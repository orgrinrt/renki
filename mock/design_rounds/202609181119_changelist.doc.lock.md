# doc changelist

One section in renki's design, and the document rendered from it. Descends
from the topic file `202609181119_topic.ls-remote-answers-within-a-deadline.md`.

## What lands

- `mock/crates/renki/DESIGN.md.tmpl`: a section, "Asking a remote for a branch
  head", saying `ls_remote_head` answers within one five-second deadline or
  returns an error, over reading the ssh configuration, the exit and the output
  together; git never prompts for a credential, and ssh is left alone wherever
  it is configured, where it may still ask on the terminal until the deadline.
- `docs/`, rendered.

## Claims the source changelist will carry

- `pin::ls_remote_head` runs git through a helper that gives up past a deadline
  of five seconds and returns an `Err` naming it, whether the child is still
  running or has exited with something still holding its output.
- One deadline covers reading `core.sshCommand` and the listing: the listing
  is given what the read left.
- The child runs with `GIT_TERMINAL_PROMPT=0` and stdin null.
  `GIT_SSH_COMMAND="ssh -o BatchMode=yes"` is set only where none of
  `GIT_SSH_COMMAND`, `GIT_SSH` and `core.sshCommand` is. The three are read
  through a trait, in that order and only as far as the first that answers, so
  the command's construction can be tested against a fake of all three.
- stdout and stderr go to two scratch files in the temporary directory, each
  created with `create_new` and removed when dropped on every path out, and
  read back once the child has exited. No thread and no `dyn` is involved.
- Tests: a child past its deadline is killed and reported inside a bound; a
  child that exits leaving its output held open is answered at its exit with
  what it wrote; a scratch file is gone once dropped, two never share a name,
  and one reads back from its start; a child inside
  its deadline hands back both streams and its exit status; a child writing
  more than a pipe holds completes; a child handed a stdin that never closes
  still reads end of file; a child that cannot start is an error; the command
  built over all eight combinations of the three ssh settings; the
  configuration read only when the environment says nothing; the configuration
  taking the whole deadline leaving the listing none; the configured value
  read from a repository's own config, and nothing when it is unset, empty,
  failing or too slow; the listing asks for the full ref and never a
  credential; and a listing pointed at an ssh that hangs comes back inside the
  deadline. Each is shown failing with its fix taken out.
