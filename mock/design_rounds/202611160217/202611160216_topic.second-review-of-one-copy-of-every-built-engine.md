# second-review-of-one-copy-of-every-built-engine


The second review of the build directory work found three things.

A build directory left unset was left to cargo, and `cargo install` still reads `$CARGO_HOME/config.toml` and an inherited `CARGO_BUILD_BUILD_DIR`. A `{workspace-path-hash}` in either is expanded against the installed package's checkout, a directory per revision, which is the build directory per key the last round meant to rule out. So the install is always given `CARGO_BUILD_BUILD_DIR`: the build directory read for the repository where there is one, and the install's own target directory where there is none or it names the hash. That target is removed with the rest once the binary is in place.

The reinstall's lock was waited on, so a second launcher's command sat silent for a whole reinstall before it ran. A launcher that finds another reinstalling skips its own update for this run and goes on to the command; the hourly check comes round again.

The scoped thread in the registry's concurrency test carries no `lint:allow(no-runtime-spawn)`. The lint, `no_runtime_spawn.rs` in `mockspace-extra-lints`, matches the text `thread::spawn` and its siblings on a line, and a scoped `s.spawn(` contains none of them, which is why the gate flagged only the two `std::thread::spawn` lines. Nothing to allow, so nothing is added.
