# doc changelist

The design of `renki`, amended to say what the review of the one engine install
branch makes true: each key builds into a target directory of its own, the key's
lock is the only lock, the collector tries that lock before it removes a key,
and the directory a build runs in is the repository's root for every build.
Descends from the topic file
`202610282212_topic.the-shared-target-directory-was-the-coordinators-proposal.md`,
which is the only open topic and is consumed whole. The previous round, closed
as `202610282145`, is an archive and stays as it was.

## What lands

- `mock/crates/renki/DESIGN.md.tmpl`, "One build per key": the target directory
  is `<cache>/builds/<key>/target` and is removed with its key, the sentences
  about one shared directory, a second lock and a directory that is not
  collected are gone, the collector's non-waiting try of the key's lock is
  said, and the toolchain paragraph names `CargoPlan::dir` as the directory the
  build runs in for the pinned and the `--engine` builds, and says that the
  `Cargo` backend's own fingerprint reads rustc in the launcher's directory
  because its contract takes no plan.
- `README.md`, "What it keeps on disk": the cargo target directory sits inside
  each built engine's directory and the collector removes it with that engine.
  The root readme is outside the phase gate and is amended here so the two
  statements land together.
- `docs/RENKI.md`, rendered.

## Claims the source changelist will carry

The `target` lock and the test that held it, deleted. The target directory at
`<builds>/<key>/target` in `ensure_built`, and the module doc of `cache.rs`
without its two shared-directory sentences. The collector's non-waiting try of
the key's lock in `Registry::gc`, with a test that holds the lock and is shown
failing before the change. The doc on `CargoPlan::dir` and the note on
`<Cargo as Backend>::fingerprint`. The repository root passed to the `--engine`
scratch build. The dead setup in the lock tests, which goes with the test that
carried it. Each is a `CHANGE` block there with its own verification.

## Not changed, and why

The per-key lock and the waiter's re-check stay as written, and so does the test
`a_waiter_finds_the_binary_the_holder_built`. The Backend contract is not
changed to let `fingerprint` read a plan's directory: it is a public trait, the
registry holds the method as a function pointer, and the launcher's key does not
call it.
