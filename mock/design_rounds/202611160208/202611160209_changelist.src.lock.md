# src changelist

The source that the locked doc changelist `202611160208_changelist.doc.lock.md` describes, and its tests. Descends from the topic file `202611160208_topic.review-of-one-copy-of-every-built-engine.md`.

## What lands

- `mock/crates/renki/src/build_dir.rs`: `build_dir` and `resolve` answer a `Result`; `.cargo/config` is read over `.cargo/config.toml`; a file that does not parse is an error naming it; `{workspace-root}` is the root and `{workspace-path-hash}` gives none. `cache::build_plan` and `engine::build` pass the error on.
- `mock/crates/renki/src/cache.rs`: `BuildLock::hold`, a lock taken without a word while it waits.
- `mock/crates/renki/src/registry.rs`: `record_and_collect` holds `<state>/registry.lock` from the load to the save.
- `mock/crates/renki/src/selfupdate.rs`: `Reinstall`, run with the command each attempt starts from, holds `<cache>/launcher.lock` for the whole reinstall.
- `mock/crates/renki/src/lib.rs`: the collection comment; `test_fixtures`, the fixture crate and the target walk shared by three test modules.
- `mock/crates/renki/src/extension/cargo.rs`: `CargoPlan::build_dir` says it reuses the units that come out the same.
- Tests: `build_dir_tests.rs` gains the target directory's precedence, a file's build directory over a variable's target directory, a cargo home among the root's ancestors, the extensionless file, a file that does not parse, `{workspace-root}` and `{workspace-path-hash}`; `engine_tests.rs` gains `a_scratch_build_leaves_its_binary_and_no_target`; `selfupdate_tests.rs` gains `a_reinstall_leaves_the_launcher_and_no_target` and `a_reinstall_waits_for_another_to_finish_with_the_shared_target`, on a fixture git repository and an install root of their own; `registry_tests/superseded.rs` gains `a_superseded_key_whose_build_lock_is_held_stays_with_its_row`, `a_recording_waits_for_the_registry_lock` and `recordings_from_many_launchers_at_once_keep_every_row_and_every_build`.

## Claims

- The two lock tests fail with the lock taken under another name: run once that way here, both red, then put back.
- Where cargo itself puts `{workspace-root}/bd` for `cargo install --path` was not observed: the workspace's hook refuses a `cargo install` with a target directory of its own outside the shared one. The expansion no longer reaches cargo, so the install never sees the template.
