# layers-meta-and-predicates

How a manifest `name.ext` is read with its layers: which files are layers,
their order, the `meta` table, includes, how tables and lists merge, and the
predicate that says when a layer or an entry applies.

## The intent

- Any number of layers `name.<layer>.ext` over the base `name.ext`, merged as
  overlays; `name.defaults.ext`, where there is one, below the base.
- A default order, defaults, base, every other layer alphabetically, then
  local, secret, private; the base has a field for a preferred order.
- Layers read from the base's directory by default, and from any number of
  `meta.overlays.include` entries, a glob matching files or a directory where
  the entry ends in `/`; an overlay's own includes are read too.
- Everything that steers the reading is under one `meta` table, the only table
  read before the parse proper.
- One schema across every layer, unknown keys refused in each: a layer is the
  whole manifest's schema, never a subset of it.
- A conditional layer, such as one for cloud sessions, loads by a predicate,
  not by a variable renki names. Predicates are defined by name under `meta`
  and used by that name alone at every site that applies conditionally, a
  layer's `meta` and a field of a tool's own schema alike.

## What the readers this replaces do

They disagree on every list. One appends hook entries from each overlay and
yet lets a clone's list for an event replace the project's; one replaces an
array whole when a local file overrides a stored one, and removes keys through
an `unset` list in its own content; one replaces a list but offers
`<field>.add` and `<field>.remove` in the content to edit it in place; one
refuses a list outright. Whatever is chosen here is what they all move to,
and none of them keeps its own steering keys in the content.

## Which files are layers

- The base is `name.ext`. A layer is `name.<layer>.ext`, same `name`, same
  `ext`, `<layer>` one word of `[a-z0-9_-]`. A file `name.a.b.ext` is refused
  by name: a layer is one word.
- `defaults` is the layer below the base. `local`, `secret` and `private` are
  layers like any other with a default place in the order.
- A file of another extension beside it is not a layer of this manifest.
- `base` is not a layer name: `name.base.ext` is refused.
- Layers are found in the base's directory and through `meta.overlays.include`.
  Two files carrying the same layer word are refused, naming both.

## The order

- Lowest first: `defaults`, the base, then the order of `meta.overlays.order`,
  later over earlier.
- `meta.overlays.order` defaults to `["*", "local", "secret", "private"]`.
  `*` is every layer the list does not name, in byte order of the word.
- It is read from the base, and from `defaults` where the base does not set it.
  An overlay setting it is refused by name: the order is decided before any
  overlay is read.
- It may not name `defaults` or `base`, which stay below. A word twice, or `*`
  twice, is refused.
- With no `*`, a layer the list does not name is refused by name, saying to add
  it or `*` to `meta.overlays.order`. A word with no file is no error.
- Under the default, a `cloud` layer sorts below a project's layer whose word
  comes after it in byte order; a base that wants otherwise writes the order.

## The meta table

- `meta` is read from every layer before anything else of that layer, and
  never reaches the manifest's own schema: a manifest's type declares no
  `meta` field.
- Its keys are renki's, and an unknown one is refused by name in every layer.
  A tool adds no key to `meta`.
- The keys:
  - `meta.overlays.order`: above.
  - `meta.overlays.include`: a list of entries, each relative to the file that
    names it: a glob matching files, or a directory where it ends in `/`. A
    matched file is a layer by the rules above or is refused by name. A glob
    is `*`, `?` and `[...]` within one path segment, the POSIX shell's own
    pattern rule, with no `**`.
  - `meta.overlays.untracked`: the layers that must not be tracked by git,
    default `["local", "secret", "private"]`. Read from the base like the
    order.
  - `meta.when`: the name of a predicate; the layer is read only where it
    holds. On the base or `defaults` it is refused: they are always read.
  - `meta.predicates.<name>`: a predicate, below.
  - `meta.replace`: dotted keys of this layer whose values replace what the
    layers below hold, rather than merging with it.
  - `meta.unset`: dotted keys taken out of what the layers below hold.

## Includes, how far

- Read to a fixed point: every layer that is read (its `meta.when` holding)
  has its includes followed, and what they find is read the same way.
- A layer whose `meta.when` does not hold is not read, so its includes are not
  followed.
- A file reached twice, by any path, is read once. A cycle therefore ends by
  itself and is no error.
- Where a layer was found has no bearing on its place: the order is by word.

## Merging

- Tables merge key by key, at every depth.
- A scalar in a higher layer replaces the lower's.
- A list, an array of tables included, appends: the higher layer's items after
  the lower's. Additions over a base are the common case, and the readers
  this replaces already add hook entries.
- `meta.replace` names a key whose value replaces the lower's whole: a list
  that should not append, a table that should not merge. A key it names that
  the layer does not hold is refused.
- `meta.unset` takes a key out of the lower layers before this layer applies.
  A key it names that no lower layer holds is refused.
- A value of one shape over another (a table over a list, a scalar over a
  table) is refused, naming both files, unless `meta.replace` names it.
- An in-content `unset` list and in-content `.add` and `.remove` become
  `meta.unset` and `meta.replace`: steering lives under `meta`, and a list
  edited item by item is a replace with the list wanted.
- After the merge, the schema reads the merged view. A key no layer may hold
  is refused naming the layer that holds it; one schema, every layer, unknown
  keys refused in each.

## Tracked and untracked

- A layer in `meta.overlays.untracked` that git tracks is refused, naming the
  file and saying `git rm --cached <file>`. renki writes no `.gitignore`.
- The secret layer is plain text when renki reads it. Keeping a secret
  encrypted is the vault's: it writes `name.secret.ext` when opened, untracked.
  renki decrypts nothing.

## The predicate

- One type, in renki. A predicate is one of:
  - `env = "<NAME>"`: holds where the variable is truthy. Truthy is `1`,
    `true`, `yes`, `on`; falsy is unset, empty, `0`, `false`, `no`, `off`;
    case does not matter. Any other value is refused by name: a reader cannot
    guess what `CLOUD=maybe` meant.
  - `shell = "<command>"`: holds where `sh -c <command>`, run in the
    manifest's directory, exits 0; exit 1 does not hold; any other exit or a
    failure to start is refused with the command and its exit.
  - `not = "<name>"`, `all = ["<name>", ...]`, `any = ["<name>", ...]`, over
    other named predicates.
- Defined only under `meta.predicates` of the base and `defaults`, the files
  always read, so no predicate depends on a layer it decides. One in an
  overlay is refused by name.
- Used by name alone: `meta.when`, and any field of a manifest's own schema
  whose kind is a predicate name. A name with no definition is refused at
  read. A cycle among `not`, `all` and `any` is refused, naming the loop.
- Evaluated when its use site is read, every time, and never kept: a shell
  predicate runs each read. An install that records an answer is the
  installer's to say, not renki's.
- renki defines no predicate and names no variable. A manifest that wants a
  cloud layer defines `cloud = { env = "<the variable its sessions set>" }` in
  its base, and `name.cloud.ext` carries `meta.when = "cloud"`.
- A shell predicate spawns a process, so it sits behind a feature and the
  unix targets; a manifest naming one on a build without it is refused by
  name.

## Provenance

- What a value resolved from now names the layer and its file, as
  `repo:local` beside `repo`, so `config get` answers which of the files it
  came from.
- The typed settings' repository file and person's file each become a stack
  of layers by these rules. The five places keep their order; inside `repo`
  and `user` the layers order as above.

## The untracked check without git

The refusal of a tracked untracked-layer must not make git a requirement of
reading a manifest. Outside a work tree, with no `git` on the path, or where
`git` fails to answer, the check is skipped in silence and the read goes on.
A test pins each of the three.

## What the first reader met

Building the POSIX reader against the design met four points it was silent
on or left to each lookup. Each is decided here so both readers keep it and
neither decides it alone.

- The stack is checked whole, once, where it is read. `stacked` refused an
  `unset` of a key no lower layer holds, and one shape over another, only for
  the key asked or one under it, so a reader walking the leaves, which the
  dump and the deserialiser do, never asked the table key above a leaf and
  passed both. The check belongs to the stack, not to the lookup: a checked
  `Stack` is what `stacked` and `resolve` take, so nothing reads an unchecked
  one. Its cost is one pass over the keys every layer holds and the tables
  above them.
- An array of tables and a list of values are two shapes. One over the other
  does not append, since the result would be a list holding both, which no
  kind reads; naming the key in `meta.replace` replaces it. An empty list,
  `[]`, holds neither, so it meets either and the other's items stand; a base
  may declare `hooks = []` and a layer add `[[hooks]]`.
- The `defaults` layer is read from beside the base only. It is always read
  and its predicates decide which layers are read, so it must be found before
  any include is followed; one reached through an include is refused by name.
- The dump writes a float in the shortest form that reads back to the same
  number, with `.0` where that form has no point or exponent, and `inf`,
  `-inf` and `nan` as TOML spells them; a date, a time or a date-time in its
  RFC 3339 text with `T` between date and time and the fraction of a second
  as written. The POSIX reader's subset holds neither and refuses both by
  name; the suite's fixtures carry the dump the Rust reader answers.

## What the first review met

A review of the POSIX reader and the host found eight more places where a
reader decided what the design must, and where the two readers would part.
Each is decided here, and a fixture pins it for both.

- A directory entry of an include naming no directory is refused, naming the
  entry and its file; a glob that matches nothing reads nothing.
- An include is resolved by the file system, a link and a `..` after it
  included, never as text, and a path holding a newline is refused, since
  neither reader can name it on a line.
- Every layer found takes a place, read or not: a layer the order has no
  place for is refused whether its `meta.when` holds or not, and the
  untracked check runs on every layer found, since a tracked secret is
  tracked whatever decides its reading.
- An item of `include`, `replace` or `unset` that is not a string is refused
  by name, never skipped.
- The predicate table is checked whole when it is read: a malformed
  definition is refused whether anything uses it or not.
- A glob keeps the shell's rule for a leading `.`: no pattern matches it, so
  an editor's swap file beside an include's glob is never taken for a layer.
- What a shell predicate prints goes to `/dev/null` in both readers, and a
  directory the shell cannot enter exits 125, which is refused.
- The host opens a file without blocking and refuses what is not a regular
  file, refuses a directory listing that ends in an error, and copies a
  variable's value instead of lending the process's environment.

The design's claim that the reader passes the stack's bare-type lints is
withdrawn: the lints read no crate of it yet, so nothing in it is called
passing them until the stack is on the registry and the crate is ported with
the contracts.

## What the fixes met

Taking the review's decisions into the POSIX reader met four points the
design still left open, decided here.

- A name a glob matches that is no layer, a directory among them, is refused
  by name, as any other non-layer a glob matches is; in a directory an
  include lists, what is no layer is passed over.
- A refusal names an include as joined to its file's directory, before the
  file system resolves it, which is what the manifest wrote.
- A name holding a newline is refused only where a reader would read or name
  it; one that is no layer and that nothing names is passed over.
- The `refused` file of a fixture is the text of the refusal both readers
  give, so a refusal's wording is the suite's, not one reader's.

The crate also gains the readme its package names, saying what is in it now:
the host, with the reading to come.

## What the second review met

A second review found the POSIX reader refusing in words the contracts could
not give, and in one place an answer they contradicted. The rule taken: each
refusal and its text is stated once in the design, the contracts' `Display`
is that text, the POSIX reader writes the same bytes and the fixtures pin it.
Where the two sides differed, each is decided here on its merits, and the
wrong side changes, the contracts included.

- `meta`, `meta.overlays` or `meta.predicates` holding a value that is no
  table [is no key of the meta table | holds a value of the wrong shape]: the
  wrong shape, since each is a key of the reader's and only its value is
  wrong. The contracts change.
- An item of a list under `meta` that is no string [one wrong-shape refusal
  for the list | one refusal naming what the item holds]: the item is named,
  as `holds an integer, which is no string`, and an item of
  `meta.overlays.order` or `meta.overlays.untracked` as `which is no word`.
  `Meta` had never checked `untracked` items; it checks them now.
- The name of a shape [`a list`, `a list of tables` | `a list of values`, `an
  array of tables`, `an empty list`]: the contracts' names, which tell all
  five apart. A merge refusal names the key and the layer below that holds
  the lower shape [the shapes alone | the key, the shapes and the lower layer
  with its line | the key, the shapes and the lower layer]: the lower layer
  without its line, since the contracts know a layer's label and no line.
  One sentence covers every pair, so the second form the POSIX reader had for
  two lists goes.
- A file that is no regular file, or cannot be read [`<file>: is not ...` |
  `"<file>" is not ...` | `<file> is not ...`]: the file unquoted and without
  a colon, as every other refusal naming a file as its subject. `BadRead::Os`
  writes neither the C call nor `errno`, which the POSIX reader cannot know,
  and keeps both for a caller that asks.
- A document that is no TOML [each reader in its own words | the POSIX
  reader's words, with the Rust reader mapping the parser's errors to them |
  the parser's words]: the parser's, `tomlfuse-parse`'s `ErrorKind` at the
  line where it stopped, so one parser speaks for a document whichever reader
  reads it. Bytes that are no UTF-8 are the parser's refusal too, so
  `BadRead::NotText` goes.
- A loop among predicates nothing uses [accepted until a use meets it |
  refused when the table is read]: refused when read, as the table is checked
  whole; the check's order is stated so both readers meet the same loop first,
  and `holds` no longer looks for one.
- A value in a refusal [`Debug` quoting | the dump's basic string]: the dump's
  basic string, which now writes `\r` and every other control byte as an
  escape too, so a refusal and a dump quote a value one way.
- The shell [`/bin/sh` in Rust, `sh` on `PATH` in POSIX | `sh` on `PATH` in
  both | `/bin/sh` in both]: `/bin/sh` in both, so a predicate meets one shell
  whatever the caller's `PATH` holds.
- The suite runs under `dash` and `bash`, and every installed `awk` of four,
  and no fixture sets a variable a shell reads itself. The base may be named
  in a fixture's `context`, so `a manifest is name.ext` has a fixture; a
  directory that cannot be listed and a file found that then cannot be read
  have fixtures; the refusals that cannot have one are named in the design.
- An inline array is an array of tables where every item is an inline table,
  not where the first one is.
- The design's sentence on the bare-type lints is a statement of fact: which
  crates they read, that this one is not among them until the stack is on
  the registry, and that whether it should be before then is open.
