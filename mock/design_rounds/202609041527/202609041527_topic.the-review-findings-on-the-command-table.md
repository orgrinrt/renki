# the-review-findings-on-the-command-table

A fix round, standing alone the way a defect found and fixed does. The round
`202609041506` closed with `Tool::commands` on the descriptor, and the review
of it found four things in the source and two in the record.

## What the review found

The descriptor check refuses the three names the crate's queries shadow and
misses the three its flags shadow. `normalize_args` strips the directory flag
wherever it sits, `dispatch` takes the engine flag off next, and `Cli::take`
takes `--cfg` off for a tool with settings, all before the first argument is
compared against the table. A command named `--dir` vanishes with no message,
one named `--engine` is refused as a flag with nothing after it, and one named
`--cfg` is swallowed as a flag. The same defect class the check exists for,
equally decidable at build time, and neither refused nor tested.

`Invocation` has five public fields and nothing marks it non-exhaustive, so a
sixth field breaks every consumer and any consumer can fabricate one, where
nothing outside the crate constructs one; it is only ever handed to a callback.
The same commit made `ResolvedSetting` public with private fields and
accessors for exactly that reason. `Tool`'s public fields are not the
precedent: a consumer builds a `Tool` and is handed an `Invocation`.

The doc on `Invocation::args` says what followed the command's name, which the
round's own test contradicts: `record a --cfg roots=[/srv]` hands the command
`["a"]`, since the launcher's flags come off wherever they sit. The same
sentence is in the design template, the readme and the rendered document.

Two tests claim more than they assert. The dispatch-order test says it checks
`locate` and `config` both still answer with a command table present and
asserts `config` only. The refusal test says the refusals settle at build time
and asserts every one of them through a runtime loop, with only the passing
case as a const assertion.

## What the record lacked

The topic argued why the engine cannot answer `homma workspace` and never
wrote down the alternative it chose against. The consumer owns `main` and
calls `renki::run`, so the launcher could match `workspace` itself before
delegating, with no change to this crate at all. The table is the better
answer for two reasons the topic carried without connecting them: the command
gets the settings resolved by the same reader the engine environment comes
from, and `Tool::defect` refuses a name collision that a hand-rolled match in
`main` cannot see, since it runs after the crate has already taken its own
names. That is the choice, recorded here since the closed round is an
archive.

The render commit carried some five hundred lines beyond this round's
section, which says `dev` had been carrying documents no round regenerated.
Not this round's to fix and worth knowing.
