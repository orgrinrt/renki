# review-fixes-for-forgetting-a-refused-build

A review pass over the branch that makes a refused build forget its branch resolution (`d3efa09`) returned merge after fixes. This topic records what it found and what the round decides. The findings are the reviewer's reading of the branch against `DESIGN.md.tmpl`, which stands in for a canon here since the repository declares no `canon_paths`.

## What the review found

The two blockers are a gap in the tests and an undeclared exception in the code. No test fails when `ensure_built` returns `Refused` where the design says `NotStarted`, for the missing lock or the unmade directory in `cache.rs`; the only `NotStarted` case that reaches `ensure_built` is the empty attempt list, which never happens in use. And `dispatch` in `lib.rs`, when it rebuilds after an eviction and that rebuild is refused, forgets nothing, with a comment arguing that the toolchain moved. The design has no such exception, and the argument does not hold, since the toolchain is part of the key, so a moved toolchain is a new key and cannot refuse on the old one.

Three smaller findings: `place<E>` turns the error into a `String` on the scratch route and back through `From<String>`, so a `Refused` taking that route comes out as `NotStarted`; `forget_resolution` deletes the record without checking that it still names the refused revision, so a launcher that resolved again meanwhile loses its good record; and the design sentence "The first is not exact either" has nothing for "either" to refer to. Two more concern placement: the mutant script sits in neither of the places the evidence rule allows, and one test repeats the code's own computation of the key.

## What the round decides

The eviction rebuild goes through the same forget as the first build, and the design gets no exception. `forget_resolution` takes the revision that was refused and removes the record only while it still names that revision. `place_via_scratch` is generic over the error, so the type survives the route. The `NotStarted` cases get tests, one for each, with the cache root made a file so that `create_dir_all` fails. The mutant script moves under `mock/research/sketches/` with the sketch it belongs to, and the repeated key assertion is replaced by one that fails when the key's inputs are not wired through.

Kept for provenance, not as intent: the reviewer's remark that the shell and perl script would be `nutshell` under the shell-stack rule. The script is a one-off measurement record and is not carried further.
