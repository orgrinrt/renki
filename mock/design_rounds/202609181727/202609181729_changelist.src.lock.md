# src changelist

Carries out `202609181727_changelist.doc.lock.md`. The one open topic,
`202609181727_topic.a-credential-helper-and-the-untested-edges.md`, is this
round's and is what everything below does.

## CHANGE: fn `ask::quiet_git` FROM terminal prompt off TO terminal prompt off and a helper's window off
File: `mock/crates/renki/src/ask.rs`
Verification: `grep -n 'credential.interactive=never' mock/crates/renki/src/ask.rs`
returns the one `args` call, placed before the environment and ahead of
anything the caller adds. The doc comment no longer says git never asks for a
credential, and says the deadline gives up on the answer while a prompt can
stay up. Tests: the command's arguments start with the two, ahead of a
subcommand added after; the `git` it builds, in an empty directory with the
global and system configuration cleared, reads `credential.interactive` back
as `never`. Taking the `args` call out fails both.

## CHANGE: test `ask::tests::a_child_reading_stdin_reads_end_of_file_rather_than_waiting` FROM run under the harness's own stdin TO run in a child whose stdin is held open
File: `mock/crates/renki/src/ask_tests.rs`
Verification: renamed
`a_child_reading_stdin_reads_end_of_file_where_stdin_never_closes`. It runs the
ignored `stdin_reports_itself` as a child of the test binary with stdin a pipe
the parent holds until the child exits, and the child prints what `cat; echo
done` under `run_within` answered. With `Stdio::null()` changed to
`Stdio::inherit()` in `run_within` the reader waits out its deadline and the
test fails; the test it replaces passed under that change.

## CHANGE: tests of `ask::ThisProcess` FROM absent TO read from a child of the test binary
File: `mock/crates/renki/src/ask_tests.rs`
Verification: `child_test` runs a named ignored test in a directory with the
ssh variables removed, the global and system configuration cleared, and the
variables the test states set; the ignored `this_process_reports_itself`
prints the three sources and what `quiet_git` over `ThisProcess` sets.
`this_process_reads_both_variables_and_the_clone_it_runs_in` and
`this_process_puts_ssh_in_batch_mode_only_in_a_clone_that_says_nothing` cover
nothing set, each variable, and the clone's `core.sshCommand`. Both ignored
tests refuse to run unless the child marker is set.

## CHANGE: tests of `pin::ls_remote_head` FROM absent TO answered from a local repository
File: `mock/crates/renki/src/ask_tests.rs`
Verification: a repository with one commit on `dev`, asked over `file://`
through `ls_remote_head` itself, answers that commit; asked for `main`, which
exists there only as a tag, it answers the branch-not-found error. These are
what `pin::resolve` and `selfupdate` reach, and the only tests that run the
wrapper rather than `ls_remote_head_from` with sources a test made.

## What the suite is worth

The new tests reach the three places the last round left unrun: the
`ThisProcess` the launcher actually passes, the wrapper both callers call, and
stdin as a child sees it where stdin is not already at its end. Each was
checked failing with its fix taken out, above. What none of them reaches is a
real credential helper: whether a given helper honours
`credential.interactive` is that helper's, and the test only shows git hands it
the setting.
