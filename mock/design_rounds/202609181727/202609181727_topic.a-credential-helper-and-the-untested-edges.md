# a-credential-helper-and-the-untested-edges

Three defects in the round before this one, found reviewing it before it
merged, and all three in what it shipped rather than in anything older.

The design says git never asks for a credential, because `GIT_TERMINAL_PROMPT`
is `0` and stdin is closed. Neither governs a credential helper. Git Credential
Manager opens a window of its own to ask, and nothing git is told about its
terminal reaches it. git has a setting for exactly this, `credential.interactive`,
and `never` is the value a helper is meant to read as "do not ask anybody". Git
Credential Manager honours it. A helper that ignores it still asks, and the
design can only say which of the two it has covered.

The same paragraph says the deadline holds over a configured ssh asking for a
passphrase. It holds over the answer: at five seconds git is killed and the call
returns an error, so the launcher moves on. It does not hold over the prompt,
because only git is killed and the ssh or the helper it started runs on, so a
prompt or a window can still be up after the launcher has moved on. The design
already says what the child starts finishes on its own, two paragraphs later;
this sentence contradicts it.

The suite has no test that reaches `ThisProcess`, the one `SshSources` that
reads this process's environment and the git configuration of the directory it
runs in, or `ls_remote_head`, the wrapper both callers reach. Every test hands
in its own sources, so the code the launcher runs is the code nothing runs.
mockspace's engine carries the same resolver and tests its `ThisProcess` by
running the test binary again as a child in a clone it sets up, with the
environment it wants and the global configuration cleared, and reading back
what the child printed. That shape carries over.

And the test that stdin is closed passes whatever the code does with stdin,
because the test harness's own stdin is already at end of file on most
runners, so a child that inherited it would read end of file too. It has to run
where stdin is a pipe that stays open, which again means a child of the test
binary, with the parent holding the write end until the child is done.
