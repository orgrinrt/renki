# the-review-findings-on-the-configuration-round

A fix round, standing alone the way a defect found and fixed does. The
configuration round, `202609041058`, closed with the contracts, the TOML store
and the `config` query in place, and the review of it found three things that
block the merge and a handful that do not, all of them in the source rather than
in the design.

## What the review found

The writer puts a top-level key into the last table when the file starts with a
header. `Toml::set` tracks the top level as "the current section is `None`",
which is true of no line once a header has been seen, so `theme` written into
`[model]\nbase = "m"\n` lands under `[model]` and parses back as `model.theme`.
The schema check after the write refuses it, so no file is corrupted, but the
first `config set` on a file whose first line is a header fails with a message
about a key nobody typed, and where the schema happens to declare the dotted
name too the wrong setting is written silently. The tests sampled three shapes
and not that one.

`config set` writes the person's file without creating its directory, where
`config edit` does. The first `config set` on a fresh machine fails on the
missing `~/.config/<ns>/`.

The published `renki` package lost its `LICENSE` in the move under
`mock/crates/`: the manifest's `include` names it, the crate root has none, and
`cargo package --list` shows it gone. The two smaller crates carry their own.

Below the line: the module doc on `config` and a comment in `cache` name the
wrong variables, `<SHORT>_CONFIG` for the file and `<SHORT>_CONFIG_DIR` for the
directory, where the file is `<SHORT>_CONFIG_FILE` and the directory is
`<SHORT>_CONFIG`. The launcher's own reinstall does not retry where the design
says it does. The retry checks one prerequisite of the three the design names.
`--cfg` is taken off the arguments for a tool with no settings, whose engine
may have its own. `renki-config` alone has no test that its readme tells the
truth, and its readme's rust block is compiled by nothing. A list of text items
writes an item holding a quote as `"a"b"`, which the item parser then refuses.
And the design said `<SHORT>_CONFIG` for both the directory and the file, which
the code resolved into two variables; the design is amended beside this round
so the deno reader in vibecheck is written against the same text.

One finding does not hold: six files were counted past the 500 line limit by
raw line count, and the `file-size` lint counts lines that are neither blank
nor comment, on which every one of them is under. The lint is right and the
tree agrees with it.

## What this round changes

The writer tracks the top level as its own region, ending at the first header,
and a top-level key added to a file that opens with a header goes above that
header. `config set` creates the directory. `LICENSE` sits beside the launcher's
manifest again and a test asserts the package ships it. The two comments name
the right variables. `reinstall` goes through the same retry as `materialise`,
after the same prerequisite check. The two prerequisite checks the design names
and the code does not do carry a `FIXME` and a red catalogue test each. `--cfg`
is left alone for a tool with no settings. `renki-config` gets the readme truth
test its siblings have and its readme's rust block compiles as a doctest. A
text item holding a quote is refused where the value is checked, since the
canonical form cannot carry it, and the test says so.

Nothing in the design changes on this side; the amendment is the design's own
and lands in the workspace.
