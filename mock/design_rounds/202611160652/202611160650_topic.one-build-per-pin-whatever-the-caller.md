# one-build-per-pin-whatever-the-caller

A launcher started under a cargo pinned to a toolchain inherits `RUSTUP_TOOLCHAIN` from rustup's proxy, and `rustc -vV` in the repository's root then answers that toolchain and not the one the root selects. Run from a plain shell in the same root it answers the rustup default. The key differs, so one pin was built twice, once per caller. Measured here: in a root with no toolchain file, `rustc -V` answered 1.97.0 plainly and 1.98.0-nightly with `RUSTUP_TOOLCHAIN=nightly-2026-05-28`, and a `cargo` subcommand run from a nightly-pinned repository saw `RUSTUP_TOOLCHAIN` set with the path unchanged. So the key's `rustc -vV` and the build's `cargo install` both drop the variables through which a caller picks a toolchain, and the toolchain is the one the root selects for every caller.

A branch pin's resolution was taken as the tip for an hour, so a moved `dev` was not seen for up to an hour. The remote is asked on every run instead, one `git ls-remote` inside its deadline; an unmoved head keys the same build, already in the cache, and makes no cargo call. The recorded resolution stays as the offline fallback, and the check that `cache_retention` is at least that hour goes with the hour.
